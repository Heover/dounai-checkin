# 豆奶后台页面签到

通过 `cua_repl` 操作 Codex 内置浏览器的隐藏标签页，完成当日签到并取得明确奖励提示。不占用用户的系统鼠标键盘，不激活桌面窗口。

## 环境与授权

- 必须有可用的 `cua_repl` 和内置浏览器 `iab`。先阅读工具返回的当前 API 文档；如果不可用，报告阻碍并停止，不改用前台鼠标或仓库脚本。
- 仅在当前请求或已有自动化授权涵盖该账号的登录、验证码和签到时执行。技能本身不提供授权，也不覆盖工具审批要求；不重复索取会话中已经具备的授权。
- 默认从本仓库根目录的 `.env` 按需读取 `DOUNAI_EMAIL`、`DOUNAI_PASSWD`。技能搬迁后，使用用户指定的项目或配置路径，不扫描其他项目或用户目录寻找凭据。
- 已登录时无需读取配置。缺少配置时停止并请用户在本地填写，勿要求在聊天中粘贴密码。
- 不输出凭据、Cookie、订阅链接、隐藏令牌或完整页面源码。不要把 `.env`、截图或账号信息加入 Git。仅向 `https://dounai.win` 的正常登录表单填写已有账号密码。
- 直接识别页面截图中的验证码，不需要 DeepSeek、OCR 服务或额外 API Key。不要运行 `npm run checkin`、`checkin:legacy` 或触发 GitHub Actions；这些是仓库中的其他执行方式。

## 后台浏览器流程

### 1. 建立本次标签页

新会话首个 `cua_repl` 调用只执行一个受支持的浏览器入口，例如：

```javascript
let taskTab = await cua.createBrowserTab(
  'iab', 'https://dounai.win/auth/login', { visible: false }
);
```

保存并复用本次返回的 `taskTab`。不要假设上次运行的 `browser`、标签页变量或元素编号仍存在，不枚举或读取无关浏览器页面。创建标签页后先检查实际地址及页面状态；地址跳到其他站点或出现浏览器安全警告时停止。

每批页面操作后读取 `getAXState()`，再选择下一步。元素编号只取自最新状态，不能照抄历史日志中的编号。页面入口可能从 `/auth/login` 跳至 `/`，已登录则跳至 `/user`。

### 2. 按需登录

- 在首页点击页面的“登录”链接，进入可见登录表单。
- 根据当前页面的“邮箱”和“密码”输入框填写配置，不使用页面隐藏字段。
- 使用 `getScreenshot()` 查看可见验证码。登录页当前使用“计算结果”输入框（曾观察到 ID 为 `captcha_code`）。
- 明确识别操作数和运算符后计算并填写。验证码输入可能自动提交登录：先检查跳转或消息，不额外立即点击“登录”，避免双重提交。
- 当明确确认未自动提交、页面仍显示可点击的登录按钮时，才通过该按钮提交一次。若只是在等待，读取页面状态或截图，不反复点击。
- 进入 `/user` 后，通过可见“控制面板”链接到 `/user/panel`。登录失败、出现两步验证或额外认证时停止并说明需要用户处理。

### 3. 检查今日状态

新加载的控制面板如果明确显示禁用的“今日已签到”按钮，则本次结果为“已签到，跳过”，不打开验证弹窗、不提交。

仅在页面显示“立即续命”时点击。该操作可能滚动页面并异步打开弹窗；若 AX 状态尚未出现弹窗，先用截图确认，不立即再次点击。

### 4. 填写签到验证

- 等待可见的“签到验证”弹窗及验证码。若仍是“加载中”，检查页面是否有错误、锁定或“已限制”；不能把加载提示当成验证码。
- 根据截图阅读完整算式，支持阿拉伯数字、中文数字和大写数字，如 `三`、`捌`；支持 `+`、`-`、`×`、`x`、`乘`、`÷`、`除`。运算符必须明确，不从两个数字直接推断加法。
- 需要看清小图时，只使用当前浏览器 API 明确支持的截图裁剪或页面可见放大方式。不要为此导入未经验证的图像库；本环境曾出现 `sharp` 导入失败。
- 仍有任一字符不确定就停止，不猜答案，不点击“换一张”反复尝试。读图后若图片变了，也不要提交旧答案。
- 截图后重新读取完整 AX 状态，定位当前验证码输入框及“确认签到”按钮。曾观察到的 ID 为 `checkin_captcha_code` 与 `checkin-submit-btn`，需在当前页面重新核实。
- 只填写可见验证码输入框；忽略 `checkin_secret` 等隐藏或无关字段。填写后刷新 AX 状态，再点击一次“确认签到”。
- 出现“正在验证签到”时等待结果的页面状态或截图，不重发提交。响应不明时结束为“未确认成功”，不自动补发请求。

### 5. 确认结果与清理

| 可见结果 | 处理 |
| --- | --- |
| 消息提示明确说明“获得了…流量和…豆丁…延长…小时” | 确认本次成功，准确记录流量、豆丁和有效期奖励；缺失项不推算 |
| 新加载页面已明确显示“今日已签到”，或服务端明确提示当天已签到 | 标记已签到，跳过，不声称本次获得新奖励 |
| “检测到签到脚本”“今日签到机会已锁定”“已限制”或 `is_blocked: true`（如果工具已返回） | 立即停止，不刷新或重试，不切换指纹、代理、账号或其他执行方式 |
| 验证码错误、页面超时、登录失败、工具不可用或无法确认奖励 | 报告具体阶段和阻碍；不将按钮变化、弹窗关闭、HTTP 200 或 `ret=1` 单独当作成功 |

不绕过证书或浏览器安全警告，不读取/重放隐藏令牌，不伪造接口请求，不隐藏自动化属性。看到站点锁定时，正确结果是停止并报告限制。

结束时关闭本次创建的临时标签页，包含成功、跳过和失败分支；不关闭用户原有标签页。如果清理本身失败，说明未能确认关闭，不为清理读取其他页面。

## 结果通知与定时调用

- 用户主动请求：简洁报告签到成功及奖励、已签到或具体失败原因。
- 定时执行：新签到成功时报告奖励；失败或需要用户操作时通知；已签到、无变化时安静结束。不重复发送手机或聊天通知，除非用户另有明确要求。
- 技能本身不会创建计划任务。当前项目约定的计划时间为每天香港时间 23:00；只有用户要求创建或修改计划时才使用可用的自动化工具。
- 定时任务可读取本文件后执行同一流程；当前对话的调度是独立配置，不随技能文件自动更新。
