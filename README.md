# 豆奶全自动页面签到

程序打开浏览器页面，自动登录、识别验证码、点击签到并发送 Server 酱3 通知。
没有人工填验证码、终端确认或交接步骤。支持本地运行；工作流文件保留北京时间 **00:07**
的定时配置，但只有启用 GitHub 工作流后才会执行。各次本地和 Actions 验证结果见下文。

## 实现方式

- 使用 Playwright 正常打开页面，由网页自身提交登录和签到请求，不重放接口或读取隐藏令牌。
- 优先使用页面中验证码的原始 PNG；其他格式使用验证码区域截图，发送到 DeepSeek 官方视觉模型。
- 模型输出算式及答案，程序独立复算，支持中文/大写数字与加减乘除；不确定时不提交，换图有限重试。
- 登录使用页面自动加载的验证码，不额外点击刷新；重试重新加载页面，避免两个加载请求重叠。
- 内联图片按原图内容校验是否改变，不把背景、边框渲染差异当作验证码更新；原图确实改变仍停止提交。
- 登录页输入验证码会自动提交，不额外点击登录；签到页填写后点击确认。
- 登录和签到各最多提交三次；服务端要求整页刷新时最多刷新一次。验证码 GET 或签到 POST 明确锁定均立即停止。
- 不修改浏览器指纹、隐藏自动化属性、解除站点锁定或禁用证书校验。

模型请求限时 20 秒、输出最多 256 tokens，关闭思考模式。只上传验证码区域，
不发送账号密码、Cookie、订阅链接或整页截图；截图不写入仓库或工作流 artifact。

参考：[DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)、
[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)。API 调用会消耗 DeepSeek 余额。

## 本地运行

需要 Node.js 20+ 和已安装的 Chrome 或 Edge。将 `.env.example` 复制为 `.env` 并填写配置，
也可通过环境变量传入。不要将真实凭据提交到仓库。

```bash
npm ci
npm run checkin
```

默认 Chrome；Edge 设置 `CHECKIN_BROWSER=msedge`。使用临时独立会话，不读取日常浏览器
密码/Cookie，不持久化登录状态。结束后自动关闭浏览器，不等待按键。

| 变量 | 说明 |
|------|------|
| `DOUNAI_EMAIL` | 必填，账号邮箱 |
| `DOUNAI_PASSWD` | 必填，密码 |
| `DEEPSEEK_API_KEY` | 必填，DeepSeek API Key，需有视觉模型权限及余额 |
| `CHECKIN_BROWSER` | `chrome`（默认）、`msedge` 或 `chromium` |
| `CHECKIN_TIMEOUT_MS` | 页面响应等候上限，默认 `30000`，范围 `1000–120000` 毫秒 |
| `SERVER_UID` / `SERVER_KEY` | 可选，Server 酱3 通知 |

## GitHub Actions

仓库或仓库可访问的组织 Secrets 中配置账号密码、`DEEPSEEK_API_KEY` 及通知凭据。
组织 Secret 必须授权此仓库访问。工作流安装官方 Chrome，使用 Xvfb 虚拟显示运行有界面浏览器，
自动识别验证码，不需要连接桌面。并发组避免定时和手动运行同时操作账号。

缺少配置、API 异常或网页流程失败时以非零退出码结束，并在通知已配置时推送失败。
启用工作流后使用浏览器入口，不再自动执行旧 HTTP/OCR 脚本；本地执行不改变远端启用状态。

日志包括白名单运行环境、浏览器版本、分阶段耗时、验证码图片字节数和识别耗时，以及登录/
验证码/签到请求的序号、HTTP 状态、业务状态和网络错误分类。Actions 摘要记录结果、最后阶段
和总耗时。请求日志不输出完整 URL、查询参数、请求体、响应原文、图片、答案、Cookie 或密钥；
不启用完整浏览器 trace、不上传页面截图。已有签到与本次新签到单独标记，锁定立即停止。

2026-09-10 [排查实跑](https://github.com/Heover/dounai-checkin/actions/runs/34429190632)
确认：登录验证码识别成功，但站点在获取签到验证码的 GET 阶段返回
`ret: 0, is_blocked: true` 和“检测到签到脚本，今日签到机会已锁定”。
页面因而一直显示“加载中”、隐藏刷新控件，确认按钮变为“已限制”。
原程序只检查提交签到 POST 的锁定，漏掉了验证码初始化的失败，将其误报为图片/页面超时。

现已改为在打开弹窗之前监听验证码 GET，先检查锁定和业务结果，再截图、识别和提交；
锁定时不再等待图片、调用识别或点击刷新。该修复纠正错误处理，**不等于恢复签到或解除站点锁定**。
诊断记录控件结构和响应状态，不记录密码、Cookie、令牌或完整页面内容。

2026-09-09 在本地内置浏览器通过页面操作成功得到 **257 MB 流量、1 个豆丁、1.5 小时有效期**。
随后 [GitHub 实跑](https://github.com/Heover/dounai-checkin/actions/runs/34327330653) 成功：
官方 Chrome 启动、DeepSeek 第一次识别登录验证码即通过、自动进入面板，确认今日已签到，
Server 酱3 推送成功。全程无人工操作。今天已签到，因此此次云端运行没有再次提交签到；
该云端运行没有验证未签到日的新奖励入账，不能保证今后不被站点识别。

页面曾提示“请刷新页面后重试”，却将按钮改成“今日已签到”，实际未入账。
因此 `ret=1` 或提交后按钮变化不单独作为成功依据：响应须有明确奖励或已签到文案。
仅首次进入面板或重新加载后才采用页面已签到状态。

验证码识别能力与站点脚本检测是两个问题。DeepSeek 已通过一次真实登录验证码验证；
即使验证码正确，站点仍可能拒绝自动化。发生 `is_blocked: true` 时程序停止，不能解除锁定。

```bash
npm test
npm run checkin -- --help
# 旧 HTTP/OCR 入口仅供明确需要时排查，仍可能被网站锁定
npm run checkin:legacy
```
